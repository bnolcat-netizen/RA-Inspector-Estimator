# RoofEstimate AI - Annotation

## Overview
Annotation is a cross-cutting concern that touches the AI pipeline, review UI, database, and PDF generation. It is one of the three hardest problems in the MVP alongside line item mapping and PDF output quality.

There are two distinct annotation states:
- **AI-suggested** - generated by Claude, unconfirmed
- **Contractor-confirmed** - reviewed and approved/edited by the contractor

Findings never go directly into an estimate without passing through contractor review.

---

## Annotation Data Model

```sql
findings (
  id              uuid primary key,
  job_id          uuid references jobs(id),
  photo_id        uuid references photos(id),
  account_id      uuid references accounts(id),

  -- Bounding box as percentage of image dimensions (0-100)
  -- Percentages are resolution-independent
  box_x           float,   -- left edge
  box_y           float,   -- top edge
  box_width       float,
  box_height      float,

  -- Finding details
  issue_type      text,    -- maps to service_catalog
  severity        text,    -- low | medium | high | critical
  description     text,    -- human-readable finding
  suggested_service text,  -- recommended line item

  -- State
  status          text,    -- ai_suggested | confirmed | rejected | edited
  ai_raw          jsonb,   -- original AI output, never modified
  edited_at       timestamp,
  confirmed_at    timestamp,
  confirmed_by    uuid references users(id)
)
```

**Key decisions:**
- Bounding boxes stored as percentages, not pixels - resolution-independent across devices
- `ai_raw` preserves the original AI output even after contractor edits - useful for future model evaluation
- `status` tracks the full lifecycle of each finding

## AI Annotation Pipeline

### What Claude receives
- The photo (base64 encoded, compressed)
- Account knowledge base (service catalog, custom issue types, terminology)
- Instruction to return structured JSON only

### What Claude returns
```json
{
  "findings": [
    {
      "box": { "x": 12.5, "y": 30.2, "width": 20.0, "height": 15.0 },
      "issue_type": "improper_flashing",
      "severity": "high",
      "description": "Flashing at chimney base appears unsealed and lifted at the left corner",
      "suggested_service": "Chimney flashing reseal and repoint"
    }
  ]
}
```

### Prompt guidance
Claude should be instructed to:
- Return bounding boxes as percentages of image dimensions
- Use issue types from the account's service catalog where possible
- Use the contractor's own terminology from the knowledge base
- Flag uncertainty (low confidence findings) explicitly
- Return an empty findings array if no issues are detected, never hallucinate

## Review UI - Interaction Pattern

The review screen shows one photo at a time with AI-suggested annotations overlaid.

### Display
- Photo rendered full-width on mobile
- Bounding boxes drawn as colored overlays (color = severity)
- Each box has a label chip showing issue type
- Tap a box to expand finding details

### Contractor actions per finding
- **Confirm** - accept as-is, status → confirmed
- **Edit** - modify description, issue type, severity, or reposition box
- **Reject** - dismiss finding, status → rejected
- **Add** - draw a new box manually for issues the AI missed

### Box repositioning (edit mode)
- Drag corners to resize
- Drag center to reposition
- Keep interaction simple - this is used on a roof on a phone

### Progress indicator
Show confirmed/total count per photo so the contractor knows where they are in the review.

## Library Options

### Annotation rendering on images
- **Konva.js** - canvas-based, good touch support, handles bounding boxes and labels well
- **Fabric.js** - similar capability, slightly heavier
- **Plain canvas API** - most control, most work

**Recommendation: Konva.js** for MVP. Good mobile touch support and manageable learning curve.

### PDF annotation rendering
Annotations need to be rendered onto images before embedding in the PDF.
Options:
- Render annotated image to canvas via Konva, export as PNG, embed in PDF
- Use sharp (Node.js) server-side to composite bounding boxes onto images before PDF generation

**Recommendation: Server-side with sharp** for PDF. More reliable than client-side canvas export across devices.

## PDF Output

Each annotated photo in the PDF should show:
- The photo with bounding boxes and severity-colored labels drawn on it
- A numbered legend below the photo listing each finding
- Finding description and recommended service per number

Example layout per photo:
```
[Annotated photo image]

1. Chimney flashing - HIGH
   Flashing at chimney base unsealed and lifted. Recommended: Reseal and repoint.

2. Granule loss - MEDIUM
   Significant granule loss on south-facing slope. Recommended: Monitor / partial replacement.
```

## Edge Cases to Handle

- **AI returns no findings** - show empty state, allow contractor to add manually
- **AI bounding box is off** - contractor can reposition in edit mode
- **Issue not in service catalog** - contractor can type a custom description, flag for catalog addition
- **Low quality photo** - detect blur client-side using Laplacian variance on a canvas element before upload. Draw the image to a grayscale canvas, apply a Laplacian kernel, compute pixel variance. Variance below a defined threshold (calibrate during Phase 0 with contractor photos) triggers a warning. This runs entirely in the browser with no extra dependency. Warn the contractor but do not block upload - they may intentionally upload a wide-angle context shot.
- **Multiple findings overlapping** - review UI shows the bounding box only for the active/selected finding; all other findings show their numbered badge only. PDF uses a greedy badge placement algorithm (8 candidate offsets, first non-colliding slot wins) so badges never stack on top of each other in customer-facing output.
